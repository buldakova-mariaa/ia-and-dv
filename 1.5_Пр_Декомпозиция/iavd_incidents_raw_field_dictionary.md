# Справочник полей датасета инцидентов SOC (iavd_incidents_raw_target)

Учебный датасет (iavd_incidents_raw_target.parquet) для треков **BI-аналитики** и **ML-инжиниринга** курса
«Интеллектуальный анализ и визуализация данных».

Каждая инцидент-карточка — это зарегистрированное событие (алерт),
сгруппированное системой корреляции в инцидент/атаку, прошедшее обработку
дежурного аналитика SOC. Одна строка = одна карточка (обычно группа
однотипных алертов).

Флаги шагов рабочего процесса (workflow): `Спам`, `Эскалировался на L2?`, `На мониторинг`,
`Заблокировать`, `SLA просрочен (взятие в работу)`, `Проверка на FP
выполнена`, `Выполнено первичное сдерживание`, `Обогащение выполнено`,
`Классификация выполнена`, `Успех brute force`, `False Positive` (флаг),
`Легитимность действия`, `Открыт для редактирования`, `Белый список`,
`Ложное срабатывание`, `Инцидент был изменен` — булевы признаки процесса
обработки. *BI*: воронка процесса. *ML*: вспомогательные признаки.

Текстовые служебные: `Принятые меры` (краткое описание мер),
`Рекомендации по плейбуку`, `Ошибки`, `Ссылка в NAD (actual)`
(HTML-ссылка на объекты системы поведенческого анализа трафика PT Network Attack Discovery).

## Структура мультизначных полей

Ряд полей хранит **массив значений в одной строке**. Формат хранения:

- элементы разделяются маркером `~~||~~`;
- для трех полей элемент является **парой «ключ|значение»** — внутри элемента
  дополнительно используется `|`.

Правило разбора: `value.split('~~||~~')` → массив элементов; для полей
типа «список пар» — дополнительно `element.split('|', 1)` → пара.

### Тип 1. Списки пар «ключ|значение» (двойной разделитель)

| Поле | Карточек со списком* | Элементов | Доля пар | Семантика пары «ключ\|значение» |
|---|---|---|---|---|
| Значение Инцидента (группировка) | 961 | 37 830 | 89 % | `значение\|роль`: `185.73.194.107\|src`, `192.168.104.135\|dst` — IP/узел/учетка + роль в событии (src/dst); ~11 % элементов — одиночные значения |
| objectLinks | 97 | 1 318 | 100 % | `учетная запись\|утилита`: `iaivd\bolshakov-a\|icacls.exe` — связь «кто какой утилитой пользовался» |
| objectValue | 79 | 1 290 | ~99 % | `учетная запись\|объект`: `iaivd\chulkov-v\|icacls.exe` — «кто с каким объектом взаимодействовал» |

\* доля карточек со списком среди непустых значений (файл-1000).

(атака = группа инцидентов).

### Рекомендации по разбору

- **BI (Qlik)**: разворот значений — `SubField(value, '~~||~~')`; пары —
  `SubField(pair, '|')`.
- **ML (pandas)**: `df[col].str.split('~~||~~').explode()`; пары —
  `.str.split('|', n=1, expand=True)` (колонки key/value);
  для текстовых признаков — объединять элементы через `'; '.join`.
- Символы `~~||~~` и `|` внутри исходных данных встречаются и как контент
  очень редко — разбор выполняется по точному совпадению `~~||~~`.
